# Dependency license review

sbom-release-diff is licensed under **Apache-2.0**. This page records the
review of every crate compiled into the binary, including build-time
proc-macros. It was reviewed for v0.1.0 against `Cargo.lock`.

## Direct dependencies

| Crate | Why it is needed | Features |
| --- | --- | --- |
| `clap` 4 | Command-line parsing, help text, value validation | `std`, `derive`, `help`, `usage`, `error-context` (default features off, so no color or terminal detection) |
| `serde` 1 | Derives the JSON report model | `derive` |
| `serde_json` 1 | JSON parsing (with the strict duplicate-key visitor in `src/input.rs`) and output | default |

There are no dev-dependencies: the integration tests run the built binary
with `std::process::Command`.

## Compatibility with Apache-2.0

All licenses in the graph are permissive and compatible with distributing
this crate, in source or binary form, under Apache-2.0:

- **MIT OR Apache-2.0**: either license can be used; both are compatible.
- **MIT**: compatible. Binary distributions must include the copyright and
  permission notice.
- **Unlicense OR MIT** (memchr): MIT is used for attribution.
- **Unicode-3.0** (unicode-ident, build time only): permissive. It requires
  its notice to accompany copies of the data files, which the third-party
  notice file below includes.

No copyleft (GPL, LGPL, MPL, EPL) or non-commercial licenses are present.

## How it is enforced

- **CI** runs `cargo deny check advisories bans licenses sources` with
  [deny.toml](../deny.toml). The allow-list is `Apache-2.0`, `MIT`,
  `Unicode-3.0` and `Unlicense`. Any other license, an unknown registry or a
  git dependency fails the build, and so does any RustSec advisory, including
  yanked crates.
- **Release archives** include `THIRD-PARTY-LICENSES.txt`, generated by
  [scripts/third_party_licenses.py](../scripts/third_party_licenses.py) from
  `cargo metadata --locked`. It contains every crate's declared license and
  the license files shipped in that crate.
- **Adding a dependency** needs an update to this page. Only add a license to
  `deny.toml` after reviewing it here.

This review checks license compatibility for distributing this tool. It is
not legal advice, and it says nothing about the licenses of the SBOMs the tool
compares.
